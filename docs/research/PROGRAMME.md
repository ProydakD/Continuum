## E-002: пересмотр, а не пересказ (проект протокола)

### Вопрос и дизайн

H-003 против H-004; H-001 против H-002. Может ли преемник пересмотреть вывод при новом контрпримере и исправить зависимые предсказания, сохранив условия прежней гипотезы?

Использовать конечные синтетические миры с известными функциями/ограничениями. A видит наблюдения, совместимые минимум с двумя заранее проверенными правилами; B получает новый различающий пример, но не ответ и не историю A; C получает только Continuum и новые запросы. Закрытый генератор хранит точное правило и тестовые случаи. Не давать C готовую таблицу скрытых ответов. A/B/C — новые процессы, единственный перенос предшествующего состояния через экспериментальную Continuum DB. Новое наблюдение B — явный экспериментальный вход, не скрытый канал памяти.

Текущий сумматор v0.2 не реализует этот протокол: нужны отдельные входы/промпты и evaluator. Даже этот опыт не проверяет свободное открытие законов — пространство правил задано экспериментатором.

### Матрица условий (не полный факторный взрыв)

| Условие | Память/обмен | Назначение |
|---|---|---|
| C0 | Состояние отсутствует, наблюдение B есть | Дефицит контекста; корректный отказ, не сравнение полной точности с информированным условием |
| C1 | Текстовая запись A + те же наблюдения/бюджет | Основной baseline представления |
| T1 | Две гипотезы, условия и зависимости в структуре | Основное сравнение pluralism с C1 |
| C2 | Один участник, все те же доступные наблюдения последовательно, равный общий бюджет | Выделить пользу смены участников от количества вычислений |
| C3 | Независимые решения без обмена, агрегатор в общем бюджете | Отделить взаимодействие от ensemble sampling |
| N1 | Заменить релевантное состояние правдоподобным нерелевантным | Проверить причинную зависимость от смысла памяти |
| N2 | Повреждённые байты/хэш либо заведомо ложная ссылка | Проверить fail-closed и чувствительность измерителя |

Сначала C1/T1 при фиксированной модели, seed, порядке и без skills. Потом по одному фактору: модель преемника; порядок свидетельств; форма представления; отдельный skill. Не сравнивать одновременно разные модели и форматы как «эффект формата». Обработать кодирование/декодирование как часть бюджета, включая обучение codec, если оно когда-либо разрешено.

### Входы, переменные, MEASUREMENT

- Независимая переменная первого сравнения: представление нерешённых альтернатив. Единица анализа — **мир/seed**, не стадия и не отдельный токен. Три стадии одного мира зависимы.
- Фиксированы: модель и её digest, параметры генерации, суммарные вызовы/время/токены, наблюдения, версии инструментов/codec, instructions hashes. Контрбалансировка порядка условий по seed до запуска.
- Первичная метрика: доля полностью корректных пересмотров — вывод соответствует контрпримеру, все заданные зависимые предсказания верны, исходная гипотеза сохранена с ограниченной областью/статусом. Проверяет независимый oracle, не голосование моделей.
- Вторичные: точность на скрытых случаях; доля ложных уверенных продолжений при недостатке данных; precision/recall обнаруженных противоречий; цена за проверенный результат; задержка; объём сообщения в байтах и входных токенах; человеческие вмешательства.
- Для заявленной уверенности — Brier score на заранее определённых бинарных событиях. Если модель не выдаёт вероятность по контракту, фиксировать missing, не подставлять 0.5 без правила.
- Учитывать failure/timeout в первичной доле как неуспех; отдельно показывать инфраструктурные отказы. Не удалять неудобные seeds и не заменять неудачный run удачным retry.

### Пороги, анализ, ограничения

Пилот после отдельного разрешения: один мир/до трёх новых процессов, только проверка осуществимости, **никакой оценки преимущества**. Размер подтверждающей серии не выбран и не разрешён: после отдельного разведочного набора оценить дисперсию, заранее выбрать N и общий бюджет, зарегистрировать до просмотра подтверждающих исходов. Повторное использование пилотного мира в подтверждающем наборе запрещено.

Предлагаемый минимально полезный эффект для обсуждения preregistration: +10 процентных пунктов первичной метрики T1−C1 при сопоставимом бюджете. Поддержка — оценка не меньше 0.10 и нижняя граница парного 95% интервала выше 0. Если верхняя граница ниже 0.10, полезный эффект этого размера не подтверждается в данной области; остальные случаи — неопределённость. Это порог решения, не установленный закон и не рассчитанная мощность. Для смены порога нужна новая регистрация, не переписывание результата.

Анализ: парная разность по seed, интервалы бутстрэпом целых миров с заранее заданным seed; таблица всех исходов и чувствительность к инфраструктурным сбоям. Для нескольких проверяемых гипотез заранее выделить одну первичную либо коррекцию Holm; не искать значимый поднабор post hoc. N и ресэмплинг фиксируются в окончательной регистрации. Критическая утечка/неразрешённое действие — немедленная остановка; ноль обнаруженных утечек не доказывает нулевой риск.

### Что изменит наш взгляд

Если T1 не лучше C1, сохранять текстовый baseline и искать, не переусложнена ли схема. Если C2 столь же хорош при меньшей стоимости, не объявлять распределение преимуществом. Если N1 не ухудшает результат, проверить копирование ответа/утечку и не засчитывать преемственность. Если C не меняет вывод после различающего наблюдения, проверить как недостаток представления, так и склонность модели к согласованию — не выбирать объяснение заранее.

## Дальнейшие направления, не готовые эксперименты

- H-005/H-006: rate–distortion по задаче — качество при сжатии текста, графа и машинного кода; отдельно стоимость codec и смена получателя. Base64/компрессия сами по себе не интеллект.
- H-007/H-008: независимая повторная проверка против повторного согласия; скрытая общая ошибка в источнике, дубликаты evidence, слепая переоценка без знания большинства.
- H-009/H-010: агент предлагает новое различающее вмешательство; оценка прироста точности на ещё не виденных исходах и сокращения множества возможных объяснений. Измерять новизну относительно информационного состояния, не словесную необычность.
- Устойчивость: удаление части памяти, смена codec, позднее опровержение, перестановка событий, восстановление после crash. Семантическая устойчивость отдельно от работоспособности CAS/lease.
- Селекция памяти: забывание для экономии против сохранения редких контрпримеров; не удалять отрицательные результаты из исследовательского журнала при абляции памяти worker.

После каждого опыта: зарегистрировать результат/ограничение, обновить конкурирующие объяснения отдельными событиями, выбрать следующий различающий тест и checkpoint. Не строить новую архитектуру только ради увеличения номера версии.
