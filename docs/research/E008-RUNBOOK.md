## Цель и границы

Проверить накопление, интеграцию и исправление причинного знания у свежих
экземпляров, а не передачу готового истинного правила. Исходные требования:
[E008-REQUIREMENTS.md](E008-REQUIREMENTS.md). Подготовительный аудит:
[E008-BASELINE-AUDIT.md](E008-BASELINE-AUDIT.md).

Используем конечные структурные причинные модели (SCM). `do(X=x)` заменяет
механизм X; условное наблюдение `X=x` механизм не меняет. Идентифицируемость
определяется совпадением ответа во **всех совместимых моделях**, а не только
скрытой истинной. Это конечная экспериментальная реализация стандартного
различия наблюдения и интервенции, не новый метод causal identification.
См. [Pearl, Causal inference in statistics: An overview](https://ftp.cs.ucla.edu/pub/stat_ser/r350.pdf).

## Уже реализованное ядро среды

- Пять измеряемых бинарных переменных V0–V4.
- Два скрытых независимых равновероятных экзогенных бита U,W.
- Неизвестная перестановка измеряемых переменных в роли R,S,T,Z,Y.
- R=U, Z=W; Y=g(T,Z) XOR bY, где g — AND/OR/XOR.
- Три допустимых семейства:
  - relay: S=R XOR bS, T=S XOR bT;
  - fork: S=R XOR bS, T=R XOR bT;
  - confounded: S=U XOR bS, T=S XOR bT.
- Неизвестны семейство, перестановка, три бита и g. Всего **8640**
  допустимых назначений параметров. Эквивалентные назначения не объявляются
  независимыми причинными структурами и не используются как априорные вероятности.
- Агентам сообщается только класс, не истинное назначение. Никакого готового
  истинного закона в исходном промпте.
- Таблицы свидетельств — точная популяционная перепись четырёх равновероятных
  экзогенных состояний, **не четыре случайных наблюдения**. Поэтому здесь
  исследуется логическая идентифицируемость, а не статистическая оценка шума.
- EA: наблюдательная таблица; EB и EC: разные одиночные вмешательства.
- Вопросы: вероятность при одном/двух вмешательствах, наблюдательная условная
  вероятность, прямая причинная связь и направленный причинный путь.
  Числа — точные рациональные значения; неоднозначность — null.
- Шесть повторяемых вопросов P образуют панель пересмотра; десять новых
  вопросов Q получает только преемник D.

Выбор начальных параметров, вмешательств и вопросов случайный, не по ответам
LLM. Детерминированный information-feasibility gate требует:

1. Множество совместимых моделей строго сужается A → AB → ABC.
2. У D есть не менее двух вопросов, идентифицируемых по ABC, но
   **не идентифицируемых ни по EA, ни по EB, ни по EC отдельно**.
3. Не менее двух вопросов D остаются неидентифицируемыми даже по ABC.
4. Не менее двух вопросов панели P сужают допустимое множество ответов.
5. Для отдельного контроля существует гипотеза, совместимая с EA, исключённая
   по ABC и дающая не менее двух опровергнутых следствий P. Этот ошибочный
   полный SCM служит предпосылкой зависимых утверждений, не готовой истиной.

Gate зависит от предоставляемых таблиц и совместимых множеств, а не от
выбранной скрытой истины среди совместимых моделей. ID вопросов не помечают,
какой ответ известен. Отдельные вопросы не считаются независимыми мирами.
Скрытые аудитные метки и наборы ответов никогда не поступают в worker.

## План условий и свежих контекстов

Точная матрица ещё должна быть реализована и заморожена.

| Условие | Разрешённая информация | Что сравнивается |
|---|---|---|
| C0 | Новый D с собственным EC, без памяти EA/EB | Зависимость результата от handoff |
| C1 | A(EA) → B(EB + память A) → C(EC + память B) → D(EC + память C) | Полноценная свободная память, любые сокращения/структуры/ссылки |
| T1 | Та же последовательность и первичные данные | Фиксированная схема утверждений, альтернатив, свидетельств, уверенности, зависимостей и ревизий |
| T2 | Те же данные; отдельные независимые линии разработки на training/validation | Модельное соглашение с произвольным внутренним payload |
| FULL-JOURNAL | Свежий D сразу со всеми EA/EB/EC без модельных выводов | Сильный одноконтекстный контроль доступности всей информации |
| SINGLE-A / SINGLE-B | Свежий D только с EA либо EB | Модельные контроли отдельных порций; EC покрывает C0 |
| REF | Детерминированное пересечение допустимых моделей | Алгоритмическая точность/воздержание по разрешённым данным |

C1/T1/T2 имеют одинаковые первичные свидетельства, права проверки источников,
ограничения памяти/вызовов и общий контракт ответов. C1 не ограничивается
обычной прозой, не обязан терять ссылки или зависимости. Различия C0 и
FULL-JOURNAL в доступе к истории — зарегистрированные вмешательства, не
дополнительные факты только для T1/T2.

Внутренний payload T2 не обязан быть JSON/RDF/графом. Общий машиночитаемый
**выход оценивания**, одинаковый для всех условий, не становится обязательной
схемой памяти. Финал A/B/C не переносится автоматически.

Две независимые линии T2 должны иметь заранее ограниченное число версий,
независимых авторов/критиков и validation-применений. Выбор финальной версии —
заранее определённый, не по held-out. Новые экземпляры получают зафиксированный
протокол без истории его разработки. История разработки сохраняется отдельно
и целиком входит в затраты.

## Гипотезы, метрики и причинные ограничения сравнения

До API необходимо реализовать и зафиксировать следующие измерения:

- **H1:** точность Q после накопления и доля правильных интегративных ответов
  относительно C0 и SINGLE-A/B; независимая проверка невозможности однозначного
  решения этих вопросов по каждой отдельной порции.
- **H2:** переход ранее допустимой гипотезы в опровергнутую; исправление
  действительно ошибочного унаследованного утверждения; исправление его
  заявленных зависимых выводов; сохранение прежнего значения/автора/основания.
  «Возможна → исключена» не называть прежней ошибкой. Естественные ошибки
  анализировать отдельно от преднамеренно внесённых.
- **H3:** первичный кандидат — парная разность T1−C1 по новым Q на уровне мира.
  Не менять направление после результатов.
- **H4:** T2−T1; обе линии и повторы усреднять **внутри мира**, не увеличивать n.
- **H5:** замена свежих участников, реальная авария после durable commit,
  противоречия, подмена источника и межмодельный перенос.
- **H6:** полная стоимость нового правильного интегративного вывода,
  отдельно стоимость правильного epistemic decision, включая воздержание.
  Правильный null не выдавать за новую определённую причинную закономерность.

Основная точность должна различать неверное ненулевое значение, правильный null,
лишний null при идентифицируемом ответе и невалидный/пропущенный ответ.
Дополнительные показатели: калибровка заявленной уверенности, ложная уверенность
в неидентифицируемом ответе, семантическая достаточность процитированных
свидетельств, сохранение авторства, ложное исправление верного утверждения.
Ссылку на существующий ID не считать доказательством правильности вывода:
oracle должен отдельно проверять, поддерживает ли цитируемая порция этот вывод.

Контрольные пары «утверждаемый полный SCM → опровергаемые следствия P»
теперь проверяются независимым oracle. У естественных модельных выводов
ещё нужно проверять реально заявленные `depends_on`, прежние значения,
сохранённое происхождение и корректность пересмотра; наличие подходящего
контрольного мира само по себе этот будущий анализ не заменяет.

## Отдельные контрольные группы

Точное число и позиции должны быть зафиксированы до API:

1. Преднамеренно ложное унаследованное утверждение и зависимые следствия,
   с сохранением происхождения вмешательства вне worker.
2. Подменённое содержимое свидетельства при известном идентификаторе:
   одинаковая узкая проверка подлинности доступна C1/T1/T2.
3. Абляция этой проверки на тех же данных — отличать пользу механизма
   проверки от пользы представления.
4. Реальное завершение контейнера после MCP-записи, до подтверждения/финала;
   преемник использует durable state, а не повторный запуск погибшего контекста.
5. Другая модель в роли преемника; при необходимости отдельная замена
   промежуточного исследователя. Не выдавать одноимённые свежие контексты за
   независимые модели.

## Статистика, масштаб и настройка сложности — ещё не заморожены

Рабочий ориентир: 60 независимых held-out миров (20/семейство), два свежих
повтора внутри каждого условия; отдельные training/validation. Прежние
шесть offline-миров — инженерная проверка, не held-out и не модельный пилот.
Случайные перестановки/параметры ограниченного класса не доказывают перенос
на другие причинные семейства.

Нужно обосновать мощность/точность оценок с явными допущениями, а не обещать
её без данных. Парный анализ по миру, стратификация по семейству,
доверительные интервалы, зарегистрированная семья сравнений и Holm.
Все неуспехи сохраняются в назначенных знаменателях; вопросы и повторы
не являются независимыми наблюдениями.

Сложность и объём памяти можно выбирать **только** по заранее заданному
правилу training/validation. Оно должно учитывать абсолютный уровень C1/T1
и полного журнала, не максимизировать преимущество T1/T2. При потолке/поле
всех допустимых вариантов — честно указать ограничение, не подбирать test
или новые критерии. После lock никаких изменений по held-out.

До запуска вывести фактическое число контекстов/HTTP-запросов, ожидаемые токены,
жёсткие лимиты запросов на контекст, байтов, времени, места и всей серии.
Разрешение API без денежного ограничения не означает бесконечный прогон
или разрешение на новую инфраструктуру. Долларовую стоимость не выдумывать,
если у разрешённого шлюза нет подтверждённого тарифа.

## Инженерная граница и gate перед API

Переиспользовать реальный Continuum MCP, изолированный Docker worker,
Supervisor, Jobs/Event Ledger и проверенный измеряющий транспорт; старые
модули не переписывать. Model API только у доверенного host, ключ не попадает
в контейнер, промпт, Git или экспериментальную память.

- Никаких previous_response_id, прежних разговоров, MemPalace, oracle,
  оценщика или исходников окружения внутри worker.
- Память — данные. Команды/код из неё не исполняются.
- Все версии состояния неизменяемы; новый head не удаляет прежнюю запись.
  Что именно доступно следующему экземпляру, измеряется в полном объёме,
  включая metadata/словарь/историю; никаких бесплатных скрытых каналов.
- Реальные raw трассы должны связывать ответ модели, tool arguments,
  MCP put/checkpoint/get и байты, доставленные следующему экземпляру.
- Нужны реальные offline Docker/MCP fixtures и отрицательные проверки
  подмены авторства, скрытой истории, пропавшей квитанции, неверного источника,
  превышения лимитов, попытки доступа к oracle и изменения архивной версии.
- Терминальные контексты не повторять. Pending допускает продолжение только
  при отсутствии живого/orphan worker и неопределённого HTTP outcome.
  Отказы, timeout и зависимые пропуски не заменять успешными повторами.
- Зарегистрировать различие transient HTTP, auth/TLS, ошибки содержимого,
  STOP и нарушения хэшей. Записать, какие события останавливают всю серию.
- Перед API: полный frozen source/data/oracle/schedule, independent evaluator,
  RUNBOOK/PREREGISTRATION, offline gate и Git-коммит с проверяемым временем.
