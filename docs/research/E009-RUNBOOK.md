## Дизайн

| Условие | Передаваемая память | Проверка |
|---|---|---|
| F0 | свободный текст | общая безопасность хранения |
| F1 | тот же свободный текст и лимит | V1: формальные ссылки, версии, зависимости, источники |
| S0 | типизированные утверждения и OR-of-AND основания | общая безопасность хранения |
| S1 | та же схема и лимит | тот же V1 |
| C0 | нет старой памяти | новые ответы, BRI не применим |
| FULL-JOURNAL | все разрешённые первичные свидетельства и исходные утверждения | без gold/автоисправления |
| T2-a, T2-b | две независимые модельные линии разработки | отдельный exploratory пакет; обе включены |
| REF | детерминированный причинный и эпистемический oracle | не равный compute-контроль |

Общий measurement channel содержит IDs, статусы, связи, версии и ответы;
он никогда не передаётся следующему участнику вместо свободного текста.
V1 читает только текущую публичную декларацию участника, разрешённые ссылки
и уведомления об изменениях. Выдаёт предупреждения, не ответ, не новый статус
и не gold. V0/V1 получают одинаковые байты первичных свидетельств; стоимость
предупреждений и самого инструмента отдельно учитывается. Измерительный
канал может направлять рассуждение во всех условиях — это явное ограничение.

Два отдельных трека: natural (без принуждения ошибаться) и controlled
(одинаковая исходная история для всех условий). Controlled включает ложные,
истинные и недостаточно обоснованные утверждения. Метка инъекции и gold
не включаются в публичный input. Сценарии фиксирует генератор, не успех LLM.

## Причинные миры и эпистемическая семантика

Новое шестипеременное семейство, три независимых fair binary источника U0/U1/U2.
X=U0, W=U1; четыре варианта связей X/Y/Z: chain, fork, confounded,
common-source. Y и Z допускают polarity bits. V=g(Z,W) XOR bV,
Q=h(V,U2) XOR bQ, g,h из AND/OR/XOR. 4*3*3*16=576 параметризаций.
Они не являются E008-мирами (шесть переменных и иной механизм/источник).
Конечный класс известен участникам, скрыта конкретная SCM. Популяционные
таблицы точные; conditioning != do. Семейство намеренно ограниченно;
число параметризаций не доказывает 576 содержательно независимых топологий.

Статус p относительно множества совместимых моделей M_t:
supported, если все M_t удовлетворяют p; refuted, если ни одна; undetermined,
если часть. Пустое M_t => conflicted (не логический взрыв).
superseded — метка старой версии, а не пятый ответ на истинность p.
Ни ложная унаследованная гипотеза, ни самоутверждение модели не сужают M_t.

Обоснования — дизъюнкция конъюнкций ссылок на источники/утверждения. Отзыв
одного набора не отменяет другой. Фактическая достаточность основания
проверяется независимым oracle; V1 проверяет лишь формальную целостность.
Монотонное поступление достоверных данных может только сужать M_t.
Возврат к undetermined допускается после явного отзыва источника/смены режима,
но не после простого добавления согласованного свидетельства.

Offline generator сначала создаёт causal-refutation и source-withdrawal
возможности, сохраняет причины отбраковки и не использует LLM-ответы.
Синтетическая метка correct/refuted и hidden model доступны только evaluator.
До final freeze необходимы также несколько обновлений, глубина >1,
смешанные основания, ложные источники, конфликт и давление памяти.

## Цепочка и изоляция

A: EA, формирование знания. B: EB+EC и разрешённая память A. C: новое
авторитетное уведомление об отзыве EB/EC и пересмотр до неопределённости.
D: новый независимый контекст, ED+EE и состояние C; новые интервенционные
источники могут вновь опровергнуть гипотезу. E: новый контекст и ранее
не предъявленные вопросы. Ни Responses history, ни measurement channel,
ни host filesystem, gold, MemPalace или прежние чаты не передаются.
Долговременная память только через Continuum; event log, current state,
evidence store и private gold логически разделены. Версии append-only.
В robustness: 1/3/5/9 передач, crash-after-commit, cross-model, forged source,
independent support, memory pressure. Все сценарии регистрируются до test.

## Объём и ресурсы — предварительно, не разрешение на запуск test

Сетка мощности: 60/120/240 миров, 2 controlled сценария, 2 повтора внутри мира;
natural отдельно, те же миры. 8 модельных условий (включая обе T2 линии).
Консервативная верхняя оценка основной серии при 240 мирах:
240*8*2 трека*2 повтора*5 участников = 38400 контекстов до robustness/T2/pilot.
Два controlled сценария пока объединены в одном контексте; при разделении
оценку следует увеличить и заново зафиксировать до freeze.
При 12000 input и 4000 output tokens/контекст — 460,8M input и 153,6M output;
это предположения планирования, не измерение. При 60–180 s/контекст и
последовательном исполнении 640–1920 часов. Конкуренция ограничивается
действительными ответами rate-limit и согласованным расписанием, не токенами.
Денежная цена неизвестна: тариф стороннего шлюза не предполагается равным OpenAI.
Pilot-кандидат: 12 отдельных training/calibration миров, F0/F1/S0/S1/FULL,
2 трека, 5 участников = максимум 600 контекстов; отдельный freeze pilot.
Модель primary-кандидат gpt-6.1-sol, фактическая доступность проверяется
реальным Responses-запросом даже при отсутствии в models list. Другой alias
не подставляется незаметно; замена требует новой calibration и audit trail.

Лимит чтения F/S — предварительно 8192 UTF-8 байта полного serialized envelope,
не только payload; одинаковые вывод/инструменты для факторных условий.
FULL-JOURNAL учитывается с фактическим полным размером; его преимущество
информационного доступа раскрывается, не выдаётся за равный объём памяти.
Инфраструктурный broker считает полный compact JSON worker reply с result,
origin/stage/sha256/trust и LF; binary backend MCP отдельно. Будущий Responses
tool-output wrapper и полный API input учитываются отдельно, а не как payload.
Учёт: input/output tokens, unknown usage, read/write bytes, MCP envelope,
версии, V1 calls/CPU/time, отказы, retries, T2 development, N=1/10/100/1000.

Draft v2 уточняет BRI как успех полного эпизода на всех четырёх контрольных
точках A–D и новом вопросе E. Предыдущий power analysis остаётся предварительным:
до выбора N нужно пересчитать мощность полного endpoint и false-retraction guardrail.
V1 не получает предыдущий measurement snapshot: это было бы скрытой памятью F1.
Полный digest каталога будущих свидетельств также не передаётся участникам:
в конечном классе он допускает подбор будущего мира перебором. Проверка каталога
выполняется брокером, публичны только уже введённые IDs/статусы/новые данные.

## Порядок и gates

0. Сертификат E008 и baseline review; сохранение parent-хэшей.
1. Draft гипотез/BRI/дизайна; power/cost sensitivity, без выбора по test.
2. Offline oracle/generator/BRI/V1, isolated MCP handoff, негативные контроли,
   границы ресурсов, provenance и crash recovery; независимый raw replay.
3. Только после offline gates и pilot lock: фактическая проверка модели,
   pilot/calibration на отдельных мирах, все исходы и потолки сохранены.
4. Final preregistration: commit, hashes, corpus/seed/splits, модель, бюджеты,
   статистика, фиксированное N, retries/stop, runtime. Текущий JSON — draft.
5. Held-out — только после всех gates; без изменения дизайна по ходу серии.
6. Независимый raw-анализ, парные миры, operational и conditional metrics.
7. Полный отчёт, таблицы, аудит требований, проверка закрытия и коммит.
