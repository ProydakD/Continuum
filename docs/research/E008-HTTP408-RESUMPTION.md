# E008-A003: отдельное возобновление после HTTP 408

## Основание и граница

После 1909 зафиксированных исходов серия остановлена на j01909: два Responses HTTP 200,
затем отправленный запрос с полностью полученным HTTP 408. Исход остаётся failed.
Это не установленное свидетельство HTTP 429, причины биллинга или аутентификации.
Ни одна проверка доступности для этой остановки ранее не выполнялась.
Пользователь разрешил продолжение, затем явно подтвердил отдельное возобновление
без повторов, с сохранением модели, часов и лимитов.

A003 — служебное, а не научное изменение после наблюдений heldout. Оно разрешает
исключение только для точного сохранённого j01909 и только после отдельного admission
и успешной ограниченной проверки доступности. Оно не делает этот исход успешным.
Первый новый контекст — j01910. Все 1909 исходов, их времена и сырые файлы сохраняются.
A001, исходная A002 и A002-R1 не изменяются; их commits и ранее выполненные GET
проверяются по прежним хешам. Старые execution-binding остаются прежними,
новые явно указывают A003 и родительскую A002-R1.

## Неизменные условия

- gpt-6.1-sol primary и gpt-6-astra secondary; исходные назначения и протоколы.
- Первоначальные начало, deadline и квоты; без сброса часов или лимитов.
- Никаких Responses-повторов, дополнительных smoke или подмены моделей.
- Только существующий bounded GET-recovery: максимум три слота с задержками
  30/120/300 секунд, прежние guard и журнал. Результаты повторно читаются,
  отправленный запрос без результата не повторяется.
- Новые HTTP 408, ошибки авторизации и прежние нетранзиентные ошибки остаются
  остановками; глобальный классификатор не расширен.
- Научные вопросы, corpus, отбор протокола, scoring и статистика не изменены.

## Проверка и последующий анализ

До нового API-запроса: unit-регрессии, локальный controller fixture без API,
сверка всего сырого префикса и ledger, отказ старых admissions для новых исходников,
проверка исторического R1, заморозка нового source-bound gate и локальный commit.
Те же четыре transaction artifacts включают исполняемые проверки A003 и rollback.

Итоговый аудитор проверяет A003 GET по сырым транспортным байтам и хронологии,
сохраняет аудит A002-R1 вложенным. Оба GET-расхода уже входят в общий журнал и
повторно не прибавляются. Поправки и смешанные версии реализации должны быть
явно раскрыты в финальном отчёте; перенос calibration/validation между моделями
по A001 остаётся ограничением. Полный объём 3426, robustness, H1–H6, REF,
ресурсы и paired-world анализ остаётся обязательным. Сам admission не результат
исследования и не подтверждение преимуществ условий.

## Наблюдаемое возобновление и первые 60 назначений D

A003 допущена на commit `6892900157fc508acb9aafff9ad609511a607674` до j01910.
Первый GET после предусмотренной задержки подтвердил доступность gpt-6.1-sol;
дополнительных smoke и повторов Responses не было. j01910 сохранён как
skipped_dependency: его назначенный предшественник j01858 также имел этот статус.
Следующие новые исходы проверены по сырым журналам, а не по сообщению модели.
Все 1909 прежних исходов, A001/A002-R1 и прежние GET остаются неизменными.

Независимая проверка первых 60/960 назначений основного D (j01891–j01950):
`{"completed": 48, "failed": 1, "skipped_dependency": 11}`.
Для всех 48 завершённых D проверен read-only контракт:
нет принятой записи памяти, вызова save_memory или сохранённого нового snapshot.
Проверены назначенные C-источники, их хеши и хронология. Первые 19 D сохраняют
историческую привязку R1; следующие назначения явно привязаны к A003.
Все эти 60 назначений C-зависимые; самостоятельные контроли D ещё не включены
в эту контрольную точку. Старый failed j01909 не превращён в успешный исход.
