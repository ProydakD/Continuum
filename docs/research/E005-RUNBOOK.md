# E-005: модель сама записывает память при разных бюджетах

## Причина следующего опыта

E-004 достиг потолка по восстановлению готового правильного правила: 24/24 в
обоих условиях, при одной ошибке вычисления в C1. Он не измерял качество записи
памяти. E-005 передаёт модели-писателю правильное исходное правило и разрешает
сохранить **только выбранный ею checkpoint**, без автоматически сохранённых
наблюдений, готового ответа или истории диалога.

Это всё ещё не открытие закономерности из данных. Узкая проверяемая гипотеза:
структурированная инструкция писателю улучшает восстановление записи при
ограниченном объёме. Конкурент: обычная компактная запись достаточна; различия
обусловлены бюджетом/ошибками записи и чтения, а не преимуществом структуры.
Общие H-003/H-004 сохраняются, не сводятся к одному конечному тесту.

## Предрегистрируемая матрица

- **6 новых миров**, по два linear/residue/switch, seed 2026101905.
- C1 — обычная компактная текстовая запись; T1 — инструкция сохранять компактный
  JSON object/array. Кодировку и выбор информации определяет модель.
- Бюджеты **48, 96, 192 байта** полного сериализованного результата инструмента:
  `json.dumps({"memory": text}).encode("utf-8")`. Учитываются оболочка, кавычки,
  экранирование и пробелы JSON; это не лимит символов/токенов. Дополнения вне
  бюджета запрещены, padding не применяется. Бюджеты выбраны до API-результатов.
- По **2 свежие пары писатель→читатель** на каждую комбинацию: 72 писателя,
  72 позиции читателя. Реплики — не независимые миры и не управляемые seed модели.
- Ещё 6 читателей REF с заведомо верной машинно-записанной памятью ≤192 байта
  и 6 EMPTY с действительно пустой базой. Итого **156 позиций** и отдельный smoke.
- Все писатели выполняются до читателей; внутри фаз порядок заранее перемешан.
  Читатель не видит условие, бюджет или идентификатор мира. Писатель не видит
  будущих запросов читателя. Общие определения функций доступны обоим.

Правило имеет единственное исключение в одной из 81 точки. Читатель получает
пять запросов (четыре обычных, один исключительный) и отдельно возвращает поля
правила, значения, сумму и разность. Частично неизвестные поля допускают `null`;
полный успех требует точного восстановления, а не удачной догадки о сумме.

## Передача и проверка памяти

Писатель вызывает `save_memory` максимум дважды. Слишком большой результат
**отклоняется целиком**, без записи и обрезки; модель получает точное число байт
и может исправить запись один раз. Синтаксис JSON не принуждается брокером:
анализ intention-to-treat, фактическое сближение форматов учитывается отдельно.
После успешной записи менять её нельзя.

Принятые байты сохраняются через настоящие MCP `put_object` и `checkpoint_task`.
В новом контексте читателя используется отдельная faithful-копия базы именно
своего писателя; `read_memory` раскрывает только записанную строку. Не передаются
исходное правило, финальный ответ писателя, история, сведения engineering DB,
идентификатор/бюджет или автоматически сохранённые наблюдения.

Неуспешный/не сохранивший запись писатель приводит к `skipped_dependency`, даже
если перед транспортным сбоем успел оставить объект. Такие позиции остаются
неуспехами в первичном знаменателе; нельзя выбирать только успешные записи.

Аудитор связывает **ответ API с аргументами save_memory**, затем с MCP-объектом,
оригинальной базой писателя, копией читателя, фактически доставленными байтами и
ответом нового API-контекста. Проверка происхождения не приравнивается к
правильности. Численные ответы оценивает уже проверенная независимая арифметика.

## Анализ до просмотра исходов

Первичный показатель — разность T1−C1 вероятности точного восстановления **всех
девяти полей правила**, равномерно усреднённая сначала по трём бюджетам и двум
репликам каждого мира. Единица анализа — **мир, n=6**, а не 156 контекстов.

10 000 парных bootstrap-повторов средних по миру, стратификация по семействам,
seed 2026101906, эмпирические индексы 249/9749 отсортированных оценок. Точный
двусторонний sign-flip по 64 вариантам знаков. Порог положительного свидетельства:
эффект ≥0.10 и нижняя граница интервала >0. Малый корпус имеет низкую мощность;
незначимость и потолок не означают эквивалентность.

Отдельные бюджеты, эффект максимального против минимального бюджета, арифметика,
неверные/неизвестные поля, повторы сохранения, объём и формат — **описательные
вторичные показатели**, не набор дополнительных тестов превосходства.

## Исполнение

Только ранее разрешённый шлюз и `gpt-6-sol`, идентичность шлюза, без независимой
аттестации весов. Работники изолированы Docker `network=none`; ключ только у
доверенного HTTP-брокера. Синтетические входы и сообщения инструмента.

Денежного/числового ограничения API пользователь не задаёт. Технически: один
worker одновременно, 300 секунд на писателя, 180 на читателя, 90 на запрос,
4096/2048 выходных токенов соответственно, 6 часов на серию. Две попытки
сохранения — внутри одной сессии писателя, **не повтор worker/API-запроса**.

При 429/502/503/504, timeout или распознанном разрыве связи неудача сохраняется;
проверка каталога той же модели после 30/120/300 секунд. Восстановление позволяет
только следующую позицию. Auth/TLS и другие нетранзитные ошибки, в том числе
в каталоге, прекращают серию. Worker не повторяется, мир/модель не заменяются.
Smoke один раз. STOP, изменение замороженного кода/входов или утечка — остановка.

Перед API: профильные тесты бюджетов и отказов, реальный Docker/MCP fixture,
отрицательные проверки удаления подтверждения чтения и подмены авторства записи.
Fixture использует программные ответы, не считается исследованием модели.

Машинная регистрация и реализация сохраняются отдельным коммитом до API.
Результат — последующим коммитом. Сырые прогоны, окружение и секреты остаются
за пределами Git; существующие E-003/E-004 не переписываются.
