## Историческая документация 0.1

Общее долговременное пространство для независимых экземпляров моделей. **Это работающий минимальный эксперимент, не готовый продукт и не «единое сознание».**

## Что уже реализовано

- Общая SQLite-база для разных процессов с WAL и атомарными транзакциями.
- Неизменяемые события и курсор изменений (для синхронизации без полной истории).
- Незавершённые задачи, временные аренды (leases), принудительный takeover с записью в журнал, контроль ревизий.
- Контрольные точки и точный следующий шаг; возобновление другим экземпляром после завершения первого.
- Пропозиции в форме `subject/predicate/object`, доказательства с источниками, противоречия и зависимости.
- MCP-сервер для Codex CLI / Desktop и отладочная консоль.
- `SessionStart` hook для автоматического напоминания загрузить общее состояние (опционально).
- Unit-тесты восстановления состояния, конфликтов, конкурентного доступа, изоляции пространств, журнала и доказательств.

## Быстрый запуск (локальный)

Требования: Python 3.11+, Codex CLI, Git по желанию. Никакой VPS и платный API не нужен.

```bash
# Распаковать архив, перейти в папку continuum-starter
python -m pip install -e .
python -m continuum.cli init
python -m continuum.cli demo
python -m unittest discover -s tests -v
```

В Windows PowerShell, если `python` не находится, попробуйте `py -3.11` вместо `python`.

`demo` моделирует два разных экземпляра, работающих с одним durable состоянием; это НЕ проверка фактического поведения Codex. Для неё — следующий раздел.

### Подключение к Codex

Установите MCP в **тот интерпретатор Python**, который запускается командой `python`:

```bash
python -m pip install -e .
codex mcp add continuum -- python -m continuum.mcp_server
codex mcp list
```

Уже запущенные клиенты перезапустите. Проверьте внутри Codex: `/mcp`. По документации Codex CLI, десктопное приложение ChatGPT и расширение IDE используют общий `~/.codex/config.toml` на одном компьютере; их фактическая доступность зависит от установленной версии клиента.

Вариант ручной настройки `~/.codex/config.toml` (подмените путь к python при необходимости):

```toml
[mcp_servers.continuum]
command = "python"
args = ["-m", "continuum.mcp_server"]
startup_timeout_sec = 20
```

Для хранения данных в конкретном месте добавьте в TOML:

```toml
[mcp_servers.continuum.env]
CONTINUUM_DB = "/ABSOLUTE/PATH/continuum.sqlite3"
```

**Важно:** изменение местоположения базы после запуска без переноса старой БД создаст *другое* пространство. Используйте один путь на всех локальных экземплярах, включая CLI и Desktop. По умолчанию это `~/.continuum/state.sqlite3`.

### Реальный тест: две независимые сессии

1. Откройте **новую** сессию Codex CLI. Дайте запрос из `examples/session-a.txt`.
2. Закройте сессию, **не используя** `codex resume` и не копируя её историю.
3. Откройте **новую** сессию Codex Desktop или CLI. Дайте запрос из `examples/session-b.txt`.
4. Проверьте, что B получил ID задачи, checkpoint и следующий шаг из MCP, выполнил содержательную проверку и сохранил новый checkpoint.
5. Повторите с третьей сессией. Сравните журнал `python -m continuum.cli events`.

Требование «без человеческого текста» относится к будущему семантическому транспорту. Этот прототип использует компактные структурированные объекты и человеческие идентификаторы как начальную совместимую схему; **он ещё не умеет передавать латентные состояния модели**.

### Опционально: SessionStart hook

Codex поддерживает хуки `SessionStart`. Добавьте к **существующему** `~/.codex/config.toml` (не затирайте свои настройки):

```toml
[[hooks.SessionStart]]
matcher = "startup|resume|compact|fork"

[[hooks.SessionStart.hooks]]
type = "command"
command = "python /ABSOLUTE/PATH/continuum-starter/hooks/session_start.py"
additionalContextLimit = 600
```

Замените путь на действительный, для Windows корректно экранируйте или используйте путь со слэшами. Код хука добавляет **только фиксированную инструкцию** обратиться к инструменту MCP, а не вставляет внешнее содержимое в контекст повышенного доверия. Это уменьшает риск prompt-injection через сохранённые данные.

Хуки не гарантируют запись финального checkpoint: это пока обязанность агента, задаваемая его инструкциями. Завершение процесса аварийно может помешать сохранению незаписанных результатов. Протокол lease позволяет другому экземпляру продолжить после истечения аренды или явно принять задачу с takeover.

## Концепция протокола

Начальное состояние агента: `continuum_bootstrap` => краткие незакрытые задачи + гипотезы + monotonic cursor. При необходимости `continuum_changes(after_seq)` получает **изменения**, а не переписывает полную историю. Операции записи создают неизменяемые события и обновляют материализованное состояние транзакционно.

Задача: `create_task` -> `claim_task` -> работа -> `checkpoint_task(..., release=True)` -> другой instance -> `claim_task` -> `finish_task`. Конкурентные изменения защищены арендой и `expected_revision`. `takeover=True` допускается для восстановления, но может прервать действующего агента.

Гипотеза: `add_claim` -> `add_evidence` -> `link_claims`. Противоречие никогда не удаляет старое свидетельство. Метка `supported` означает только наличие записанного поддерживающего evidence, **не научную истинность**.

## Ограничения и безопасность

- Локальный прототип **не аутентифицирует агентов**, workspace — логическая группировка, **не ACL**. Не подключайте посторонних.
- Не публикуйте этот stdio-сервер напрямую в Интернет. Публичный HTTP требует отдельного шлюза, auth, TLS, ограничений доступа и проверок.
- Сохранённые текстовые поля — **данные, а не инструкции**. Тексты из непроверенных источников не должны получать привилегии системных промптов.
- SQLite отлично подходит для первого теста на одном компьютере; для многих физических узлов спроектируем PostgreSQL и сетевой API.
- Запись знаний **не равна** обучению весов модели и не создаёт непрерывного фонового вычисления при остановленных агентах.
- Подключение через MCP не гарантирует, что модель сама вызовет нужный инструмент; протокол, хуки и измеримые сценарии это улучшают.
- Автоматическое чтение приватных чатов/проектов **не включено**. Секреты, ключи и персональные данные сохранять нельзя.
