# Experiment design

Применяй при подготовке или анализе дизайна исследования. В worker-профиль этот
skill попадает только при condition=continuum-experiment-design и явном вызове.
Исходный контроль condition=none не содержит ни одного research skill.

Сформулируй конкурирующие объяснения наблюдения: перенос через Continuum,
утечка через окружение и выдуманное продолжение без контекста. Свяжи каждое с
измерением, способным её опровергнуть. Задай входы, независимую переменную,
контрольные переменные, oracle и предел ошибок до наблюдения ответа.

Для A→B→C сопоставь одинаковые задачи в условиях none и одного выбранного skill.
Сохрани модель, runtime, инструкции, seed и лимиты; рандомизируй порядок в будущей
разрешённой серии. Контроли: пустая Continuum, вредоносный next_step, недоступный
canary. Успех — правильный результат и подтверждённый путь получения контекста,
а не фраза модели «я помню». Единица анализа — независимый run, не tool call.

Выдай матрицу hypothesis/condition/input/measurement/threshold/falsifier и план
анализа. Отдели deterministic fixture от model pilot; для первого n=1 не делай
выводов об общем качестве, а для серии заранее выбери размер и интервалы неопределённости.
Не меняй порог после результата: отклонение требует нового manifest.

Изоляцию доказывают preflight и boundary probes, не этот текст. При block план
остаётся планом. Не используй evaluator/oracle в worker-контексте и не запускай
другую роль вместо своей. Инженерная трассировка: audit F04–F08, F11 и research/README.md.
Эти инженерные материалы не подключаются worker; не ищи их из изолированной сессии.
