# Session handoff

Применяй в condition=continuum-session-handoff с явным вызовом. Этот skill не
входит в none и не создаёт независимую сессию: её создаёт supervisor.

Из bootstrap сохрани cursor и идентификатор подходящей незавершённой задачи.
Прочитай текущую задачу и связанные объекты/evidence. Сопоставь её с порученной
стадией, не превращая свободный next_step в новый запрос. Пустой, неправильный
или повреждённый predecessor означает needs_context, не успешный handoff.

Арендуй прочитанную ревизию. Долгая работа требует renew раньше TTL; heartbeat
supervisor может изменить revision, поэтому непосредственно перед checkpoint
перечитай задачу. Conflict требует нового чтения и проверки владельца, не
повтора stale write и не принудительного takeover живой аренды.

Checkpoint включает проверенный результат, ссылки и хэши, оставшиеся гипотезы,
явный следующий тест и границы незавершённого. Release освобождает задачу.
Finish допускается лишь для выполненного критерия текущей задачи, не потому,
что процесс заканчивается. После аварии явно отделяй durable state от того,
что могло остаться только в stdout.

Не подмешивай прежние чаты, MemPalace, соседние workspaces и supervisor logs.
Техническая недоступность этих каналов проверяется отдельно; один CODEX_HOME
не доказывает её. Инженерная трассировка: audit F04–F06, F08–F09 и research/README.md.
Эти инженерные материалы не подключаются worker; не ищи их из изолированной сессии.
